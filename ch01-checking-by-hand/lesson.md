# 1. Checking by Hand, and Why It Falls Short

Before you write a single test, you should see what most of us do first. You run the program, read the output, and decide it looks right. Often that is enough. This chapter shows where it stops being enough, and the chapters after it build the replacement.

The chapter has three steps and a summary. You will run the invoicing library on the invoice from the last chapter, run a deliberately broken rule next to the real one, and then write the same check as a test. The library itself does not change in this chapter.
